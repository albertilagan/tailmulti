# Automatic custom-hostname implementation

Historical implementation plan for 0.4.0. The later global switch restores all
Tailmulti-owned DNS entries when turned off; per-account disconnect still retains
name ownership. See [activation](ACTIVATION.md) for the current lifecycle.

The acceptance case is ordinary access to an HTTPS service whose public hostname resolves to a tailnet address. Its IPv4/IPv6 translation and TLS path already worked with a process-local DNS override. The fix must not require changes to the remote service, its DNS or Tailscale account enrollment.

1. Compile an immutable canonical-address index from retained leases, including disconnected/removed owners. Translate only uniquely owned, currently active Tailscale addresses. A collision remains blocked even if one owner disconnects. Keep per-account MagicDNS answers unchanged.
2. Add bounded forwarding for otherwise-unhandled system DNS queries to the Mac's ordinary physical-network DNS servers. Do not use a public resolver vendor, forward ordinary internet DNS through either account, or call the system resolver recursively. Preserve ordinary responses. Translate A/AAAA answers, follow bounded CNAME chains, and suppress unusable HTTPS/SVCB address hints. Never claim DNSSEC validation for rewritten data.
3. Before handing out a translated custom answer, persist exact hostname-to-account ownership and install its owned split-DNS entry. Preserve CNAME-chain names as appropriate. On disconnect, removal, crash or restart, known names cannot silently resolve through another account or ordinary DNS. Recheck current mapping after forwarding/persistence to reject stale replies. Bound stored names and concurrent work.
4. Install an owned, temporary default DNS service in macOS SystemConfiguration only during approved active networking. Use a distinct Tailmulti key and never overwrite another service. Read original primary-service DNS independently of this overlay and bind forwarding sockets to that physical interface. Remove the temporary service on normal shutdown and process death. Retained exact-name entries and synthetic reject guards remain until the existing explicit DNS restoration action.
5. Update native activation/stop explanations to describe default DNS forwarding, automatic private-address translation, normal-resolver restoration and retained private-name protection. No new per-domain setup is required for this public-DNS case. Browser DNS-over-HTTPS that bypasses macOS, private corporate DNS forwarding, and subnet routing remain separate limitations.
6. Test A/AAAA and CNAME translation, unchanged public DNS, malformed responses, DNS hints, ambiguous and disconnected addresses, historical ownership, late replies, persistence/host failures, UDP/TCP fallback and bounded concurrency. Test native DNS snapshot/ownership/lifecycle through injected operations and read-only APIs. Build a separate signed candidate, without replacing the registered bundle.
7. Before activation, explain that normal system DNS will pass through Tailmulti while internet connections remain on the normal network. Then validate normal system lookup and HTTPS without overrides, unrelated public DNS, both tailnets and disconnect isolation. Passing unit/build checks does not establish these live outcomes.

The state schema gains retained custom-name ownership and the engine identities' historical canonical addresses. Older binaries reject unknown state fields; the store retains private legacy metadata as `state.before-v0.4.json` before its first schema-changing save. Do not imply bundle-only rollback is sufficient or restore that older snapshot after new leases have been issued. Downgrade must retain current leases, account state and DNS tombstones.

## Supported platform subset and unresolved live checks

The implementation uses `SupplementalMatchOrders=[100000]` as well as `SearchOrder`, following the platform research. It accepts one unambiguous physical primary service, including IPv6-only networks, and refuses competing IPv4/IPv6 primary services or DNS that needs a VPN. It reads a fresh native snapshot before and after each forwarded request rather than caching server addresses. A vanished or replaced temporary resolver blocks routing on the next reconciliation; it is never overwritten or silently reinstalled.

Exact-name files are durable before an answer, but macOS consumes resolver changes asynchronously. File persistence alone does not prove the system has loaded the rule. Live testing must cover that first-answer/crash boundary, resolver selection, stale canonical caches, scoped queries, network switching, shutdown and process death. The temporary resolver is preferred, not an exclusive interception mechanism. Browser-owned DNS, managed encrypted DNS and more-specific foreign split resolvers can bypass it. Do not advertise an absolute DNS leak guarantee from offline tests.
